# Handover 2026-11-19: data, models and runs for the faster PC

For Patryk. What was produced on the laptop since 2026-11-07, where to get it, how to
check it, and which training and evaluation runs to do next. Background in the
[project log](log.md) (entries of 2026-11-18 and 2026-11-19).

## What happened in short

- **MuJoCo renderer** (`mujoco_scene.py`): the same scene and the **same layouts** as Isaac
  (`sim_core/layout.py` reproduces `isaac_scene.place_obstacles` exactly). Mean pixel
  difference to the Isaac images 3.6 / 255. Closed-loop test without Isaac:
  `drive_mujoco.py`. → [mujoco](knowledge/mujoco.md)
- **DAgger round 1** in MuJoCo: `resnet18_001` drove 180 episodes on layouts 200000+,
  `dagger.py` labelled the 20,015 frames, retrained → `resnet18_dagger_r1`. Closed loop:
  discrete 83 → 98 % success, no collision in 300 episodes.
- **Direction model** (`train.py --task dir`): 8 directions + speed instead of L / F / R,
  labels from the tuned directional expert (`label_directions.py`, strong repulsion: backs
  off near obstacles). → [training](knowledge/training.md#direction-model---task-dir-2026-11-19)
- **Expert-planned samples** (proposal [0008](proposals/0008-expert-planned-sampling.md),
  accepted): `scene_gen_mujoco.py --plan` / `scene_gen.py --plan` render hot spots and
  start / recovery sequences instead of the 5 × 5 grid. The first data with back-off
  examples (7 % of the direction labels).

## 4. Runs to do

Same settings as before (12 epochs, batch 64, ResNet18), add `--workers` to taste:

```bash
# A: control for the DAgger result (if not finished on Colab)
python train.py --data data/grid --labels data/grid/labels_plus_mujoco_grid.jsonl --out runs/resnet18_mjgrid
# Direction model, grid + planned samples (back-off examples)
python train.py --data data/grid --labels data/grid/labels_dir_plans.jsonl --task dir --out runs/resnet18_dir_plans
# Direction model, grid + DAgger + planned samples
python train.py --data data/grid --labels data/grid/labels_dir_dagger_plans.jsonl --task dir --out runs/resnet18_dir_dagger_plans
# Optional: --seed 1 / --seed 2 of the above (seed spread, as for resnet18_s1 / _s2)
```

During direction training the val recall of BL / B / BR shows `nan`: the Isaac grid has
no back-off cases. Whether backing off was learned shows only in closed loop.

**Evaluation**, always on layouts 100000–100099 (the default), three motion modes:

```bash
M=runs/resnet18_mjgrid/model.ts
python drive_mujoco.py --model $M --count 100 --out runs/eval/mjgrid/discrete
python drive_mujoco.py --model $M --count 100 --side-forward 0.1 --out runs/eval/mjgrid/side_forward_0.1
python drive_mujoco.py --model $M --count 100 --filter-alpha 0.7 --out runs/eval/mjgrid/filter_0.7
# direction models: add --directional (with --filter-alpha 0.7 the velocity is filtered)
python drive_mujoco.py --model runs/resnet18_dir_plans/model.ts --directional --count 100 --out runs/eval/dir_plans/plain
python drive_mujoco.py --policy direxpert --directional --count 100 --out runs/eval/direxpert   # upper bound
```

Each run writes `eval.json` (success / collision / off-road / timeout rates) and
`episodes.jsonl` (paths). `--view --delay 0.05` shows a run in the MuJoCo viewer.

**How to read the DAgger result:** if `resnet18_mjgrid` (A) drives about as badly as the
baseline (≈ 17 % stuck with discrete steps), the gain of `resnet18_dagger_r1` comes from
the visited states, i.e. DAgger. If A is as good as DAgger, it came from seeing MuJoCo images.
